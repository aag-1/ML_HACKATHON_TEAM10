# PathSnap: Map-matching & Route Reconstruction

PathSnap matches noisy GPS observations to a road network and reconstructs the route a vehicle actually drove. It works in two layers: a machine-learning candidate scorer, followed by HMM/Viterbi sequence decoding. The system is served by a FastAPI backend (laptop 1) and an evaluator UI (laptop 2).

> **Status:** Phase 1 is complete (data preprocessing, feature engineering, model training and comparison).
> Phase 2 is still to come: Bayesian optimisation, HMM/Viterbi, API, UI and the final report.

## Repository layout

```
src/pathsnap/          reusable library (imported by the scripts now and by the API in phase 2)
  config.py            paths and every fixed setting (documented in docs/decisions.md)
  data.py              raw-file loading (route loaded only on request, so no leakage)
  geo.py               per-trip UTM projection and point-to-segment geometry
  preprocess.py        time gaps, smoothed speed/heading, moving flag
  labels.py            monotonic DP alignment: route -> per-observation labels (with self-check)
  candidates.py        KD-tree candidate generation (arcs within 50 m, max 10)
  features.py          13 features per (observation, candidate)
  metrics.py           Top-1, Macro F1, log loss, route continuity (with self-check)
scripts/
  01_eda.py            dataset exploration: tables, plots, Folium maps
  02_build_dataset.py  preprocessing + labels + candidates + features -> data/processed/*.parquet
  03_train_models.py   5 models, 5-fold GroupKFold CV + student-test evaluation, plots
  04_phase1_pdf.py     phase-1 summary PDF generator
  05_bayes_opt.py      Bayesian optimisation of the selected model (Optuna)
  06_hmm.py            HMM decoder tuning + evaluation
  07_export_artifacts.py  model + decoder settings for the API
  08_report*.py        technical report generator
docs/                  per-step documentation and decision log
results/               CSV/JSON experiment outputs (all report numbers come from here)
figures/               PNG plots
maps/                  interactive Folium HTML maps
models/                trained models (*.joblib, regenerated by script 03)
data/raw/              organiser dataset: train/ and student_test/ (not committed)
data/processed/        generated parquet files (not committed)
```

## Setup

Requires Python 3.13 (tested on macOS).

```bash
python3.13 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

Place the organiser dataset at `data/raw/train/<trip>/...` and `data/raw/student_test/<trip>/...`.

## Reproduce phase 1

Run each in order from the repository root:

```bash
.venv/bin/python scripts/01_eda.py
```

```bash
.venv/bin/python scripts/02_build_dataset.py
```

```bash
.venv/bin/python scripts/03_train_models.py
```

```bash
.venv/bin/python scripts/04_phase1_pdf.py
```

Approximate run times on an 8-core laptop: 30 s, 15 s, ~20 min, 5 s.

Self-checks:

```bash
PYTHONPATH=src .venv/bin/python -m pathsnap.labels
```

```bash
PYTHONPATH=src .venv/bin/python -m pathsnap.metrics
```

## Data partitions and integrity
- **train (80 trips):** fitting and 5-fold GroupKFold CV. Trips 33 and 54 are excluded from training because their reference routes lie 120–140 m from the GPS. They remain in the EDA.
- **student_test (10 trips):** development-stage comparison only.
- **evaluator (10 trips, IDs 15, 17, 23, 30, 49, 59, 67, 73, 87, 94):** not used during development.
- Reference routes are used only to build training labels and to score predictions. They are never model inputs.
